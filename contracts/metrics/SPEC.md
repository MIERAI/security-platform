# Contract: metrics — version 1.0

| | |
|---|---|
| contract | `metrics`, version **1.0** |
| registry | [`registry.json`](registry.json) (schema [`registry.schema.json`](registry.schema.json)): every metric name, type, labels, producer, stability |
| conformance | the `prom` assertions in `conformance/cases/{ledger,remediation,scorecard,runner}/*`; `tests/test_contracts.py` checks that every metric the generated rules, dashboards, SLOs and scorecard catalog use is registered |

The key words MUST, MUST NOT, SHOULD, SHOULD NOT and MAY are used as in RFC 2119.

The Prometheus series are the platform's **public API**: alert rules, recording rules, dashboards, SLO definitions
(`dist/`, generated by `generators/gen.py`), and scorecard controls (`type: metric`) are written against them. An
implementation of a component MUST emit the series its producer row lists, with the same names, types and label keys.

## 1. Format and delivery

- Prometheus text exposition format 0.0.4; every family has `# TYPE` (`counter` when the name ends in `_total`, else
  `gauge`) and SHOULD have `# HELP`. Within one published file a family appears once (HELP/TYPE once, samples grouped).
- Producers write `.prom` files (written atomically): `<data>/latest/<collector>.prom`, `<data>/metrics/ledger.prom`,
  `remediation.prom`, `export.prom`, `scorecard.prom`; the hub runner merges them with its own series into
  `<data>/metrics/security-platform.prom` and hands that text to the sinks (textfile, Pushgateway, remote write,
  Kubernetes ConfigMap, …; `adapters/sinks.py`).
- Timestamps are values in **epoch seconds** (`*_timestamp_seconds`); durations in the unit their name says.

## 2. Naming and labels

- Names: `security_[a-z0-9_]+`. Counters end in `_total` and never decrease (they are recomputed from persisted
  state, e.g. `reopened_count`, so they survive restarts).
- **Labels MUST NOT carry asset details** (host names, addresses, image names, repository names, finding ids, user
  names). Allowed label keys are those in the registry: `collector`, `site`, `job`, `sink`, `layer`, `severity`,
  `status`, `sli`, `quantile`, `dimension`, `pillar`, `function`, `state`, `asset_class`, `priority`, `result`,
  `version`, `release`, and collector-defined ones of the same nature (`cluster`, `source`, `kind`, `feed`, `store`).
- `collector` is added by the runner to every collector-reported metric (findings document `metrics`).

## 3. Stability classes (registry `stability`)

| class | promise |
|---|---|
| `stable` | name, type and label keys change only by the two-step rule: both names exported for at least one minor release and two weeks, generated rules and dashboards moved, then the old name dropped (`docs/upgrade.md`). Adding a label is a minor change; removing one is two-step. |
| `collector` | defined by one collector, versioned with it; same rules once a generated rule, dashboard, SLO or catalog control uses it (`used_by_generated: true`). |
| `target` | specified here, not yet emitted by the reference implementation (known deviations). New implementations SHOULD emit them; consumers MUST NOT depend on them yet. |
| `deprecated` | still emitted; `replaced_by` names the successor. |

## 4. Heartbeats (what makes "no data" visible)

Each producer exports when it last did its job: `security_runner_tick_timestamp_seconds` (+ threshold
`security_runner_tick_max_gap_seconds`), `security_collector_last_run_timestamp_seconds`,
`security_collector_last_good_run_timestamp_seconds` (+ `security_collector_expected_interval_seconds`),
`security_ledger_last_update_timestamp_seconds`, `security_remediation_last_update_timestamp_seconds`,
`security_scorecard_last_compute_timestamp_seconds`, `security_metrics_published_timestamp_seconds`. An implementation
MUST keep them truthful: a component that did not run MUST NOT refresh its heartbeat.

## Known deviations

| id | current behaviour (reference) | target | case |
|---|---|---|---|
| METRICS-D1 | three collector metrics are counts that can go down but end in `_total`, so they are exposed as `# TYPE … counter`: `security_secrets_total` (secrets-files, k8s), `security_repos_total` (codehost-github, codehost-gitea), `security_detection_rules_total` (detection). `rate()`/`increase()` on them would misread a decrease as a reset. | gauge names without `_total` (e.g. `security_secrets`, `security_repos`, `security_detection_rules`), introduced by the two-step rule; none of the three is used by a generated rule or dashboard today | — (collectors need external tools) |

See also RUNNER-D2 in [runner](../runner/SPEC.md): `security_runner_job_missed_slots_total` and
`security_runner_job_pending_slot_timestamp_seconds` are `target` entries of the registry.
